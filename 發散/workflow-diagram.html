IdeaTrail — AI 引導式專案發想系統 流程圖

使用者從「開始設定」到「想法牆」實際會走的路徑，以及每個 Agent 在每一步問了什麼問題

每一步使用者實際會被問的問題（展開查看）
① 開始設定（團隊條件）▶
一次填完，供 Method Selector 與每一個 Framework Agent 當背景資訊使用。
  1. 團隊人數？
  2. 可用時間？
  3. 技術背景？（自由文字）
  4. 領域偏好？（自由文字）
  5. 限制條件？（例如「希望有實際使用者」「不要太難」）
  6. 是否已有明確問題？（是／否／不確定）→ 是的話：那個問題是什麼？
  7. 是否已有既有產品／題目想改造？（是／否／不確定）→ 是的話：想改造的對象是什麼？
② 痛點發想 Pain Discovery（discovery stage，5 題）▶
給還沒有痛點的團隊用；每題是不同的回想線索，「想不到」會被 AI 換角度提示而不是退回。
  1. 回想最近一個平常的日子，從起床到睡前，哪一刻你嘆了口氣、皺了眉，或心想「怎麼又這樣」？
  2. 你有沒有在用 Excel、便利貼、LINE 記事本、截圖，或某種土法煉鋼的方式硬撐某件事？那件事是什麼？
  3. 最近有什麼事，你得等別人回覆、確認、排隊，或等某個東西準備好才能繼續？
  4. 有什麼事你每週都在重複做，或是一直被別人問同一個問題？
  5. 想一個你身邊的人（家人、同學、同事、室友），他最近抱怨過什麼？
彙整產出：1~5 筆痛點，每筆含 statement／who／context／current_workaround，寫入痛點庫
痛點導向 Pain Point（6 題）▶
先有痛點、才有解法：從一件具體的麻煩事出發，逐層深挖同一個問題。
  1. 最近有什麼事讓你覺得麻煩、卡關，或者一直在用不太好的方式應付？
  2. 誰會遇到這個問題？是你自己，還是某一群特定的人？
  3. 現在大家是怎麼解決（或忍受）這個問題的？
  4. 為什麼現有的解決方式不好？哪裡讓人不滿意？
  5. 這個問題發生的頻率有多高？是每天都碰到，還是偶爾才遇到？
  6. 如果這個問題被解決了，對當事人來說，價值或差別會是什麼？
彙整產出：固定 3 個 Concept，是解決「同一個痛點」的三種不同作法，不是三個不相關題目
使用者旅程 User Journey（8 題）▶
把處理這個問題的完整流程攤開，從最麻煩的那一步找切入點。
  1. 這個問題通常會在什麼情況下發生？
  2. 從開始處理到完成，你通常會經歷哪些步驟？
  3. 在每個步驟中，你會做什麼、使用哪些工具，或與哪些人互動？
  4. 在整個流程中，哪個步驟最麻煩、最花時間，或最容易出錯？
  5. 這個困難會對你造成什麼影響？
  6. 如果可以改善一個步驟，你最希望改變什麼？為什麼？
  7. 你覺得有哪些地方可以變得更簡單、更有效率或更不容易出錯？
  8. 如果有一個工具或系統能改善這個流程，你希望它幫你完成什麼事？
彙整產出：固定 3 個 Concept，每個都對準流程中的某一步（優先是最麻煩、最想改的那一步）
SCAMPER（8 題）▶
針對一個現有對象，用七個固定角度逐一逼問「還能怎麼改」。
  1. 你想要套用 SCAMPER 的對象是什麼？可以是現有的產品、服務、流程，或一個粗略的題目方向。
  2. Substitute（替代）：這個對象裡，有哪個元件、角色、材料或做法可以被替代掉？替代成什麼？
  3. Combine（結合）：可以把這個對象和什麼其他東西、功能或服務結合在一起？
  4. Adapt（調整）：有沒有其他領域的做法，可以拿來調整套用到這個對象上？
  5. Modify（修改）：這個對象的某個特性（大小、頻率、強度……）如果放大或縮小，會發生什麼事？
  6. Put to another use（其他用途）：這個對象或它的一部分，還可以用在完全不同的用途或使用者身上嗎？
  7. Eliminate（消除）：如果拿掉這個對象裡的某個部分，會變得更簡單、更聚焦嗎？拿掉什麼？
  8. Reverse（反轉）：如果把這個對象的順序、角色或邏輯反過來，會變成什麼樣子？
逆向思考 Reverse Thinking（4 題）▶
故意想最爛的點子，挖出爛在哪裡，再把最有趣的一個調轉成有商機的方向。
  1. 這次想圍繞的情境或對象是什麼？可以是一群使用者、一個場景，或一個粗略的題目方向。
  2. 先反過來想：針對這個情境，故意想 3～5 個「最爛、最沒用、根本沒人想用」的點子。越荒謬越好，不用擔心丟臉。
  3. 這些爛點子裡，讓你覺得「最讓人討厭」或「最沒用」的地方到底是什麼？具體說說看。
  4. 挑其中一個你覺得最有趣的爛點子，試著把它「調轉」或「修正」成一個說得通、甚至有商機的方向，會變成什麼樣子？
類比法 Analogy（4 題）▶
借用其他領域已經解決類似結構問題的做法，類比套用到自己的情境。
  1. 你想解決的問題或情境，用一句話簡單描述一下？
  2. 有沒有其他完全不同的領域、產業，甚至大自然裡，已經有很成熟的方式在處理「結構類似」的問題？不用跟你的題目像，結構像就好。
  3. 那個領域具體是怎麼解決的？他們的做法或設計邏輯是什麼？
  4. 如果把那個做法的邏輯「借」過來，套用在你原本的問題上，會變成什麼樣子？
能力對應問題 Capability Mapping（4 題）▶
從已經會的技術出發反推能解決什麼問題，並檢查問題本身是否值得做（避免為技術找題目）。
  1. 你們團隊目前比較拿手、或很想拿來練功的技術/工具是什麼？可以列多個，例如電腦視覺、LLM、某個框架。
  2. 這個技術跟「隨便找個題目套用」比起來，有沒有什麼是它特別擅長、別的做法很難做到的地方？
  3. 想像一下，誰的生活或工作裡，剛好卡在一個「只有這個技術特性」才能解決的問題上？
  4. 如果拿掉這個技術限制，單純只看這群人的問題本身，這個問題本身重要嗎？值得做嗎？
HMW — How Might We（4 題）▶
把觀察到的問題改寫成一句「我們可以怎麼做，讓...？」，再針對這句話大量發想解法。
  1. 你觀察到的原始問題或困擾是什麼？不用講得很完整，先講你實際觀察到的現象就好。
  2. 試著把這個問題改寫成一句「How might we ...？」的句子。例如：How might we 幫助學生快速找到空教室？
  3. 針對你剛剛寫的這句 HMW 問題，盡量列出幾個可能的解法，不用完整、越天馬行空越好。
  4. 剛剛列的這些解法裡，你自己最想深入研究的是哪一個？為什麼？
混搭法 Mash-up（4 題）▶
分別列出對象、痛點、技術三份清單，各自發散後再隨機強迫組合。
  1. 列出 3 個可能的目標族群或使用情境（例如「晚班的護理師」「通勤中的學生」），先不用想他們的問題是什麼。
  2. 先不管上面列的對象，單獨列出 3 個你們常聽到、常觀察到的痛點或需求。
  3. 再列出 3 個你們感興趣、或想嘗試套用的技術／媒介／形式（例如 AR、LINE Bot、語音助理、感測器）。
  4. 從上面三份清單裡，各挑一個「對象 + 痛點 + 技術」硬湊在一起，這個組合可能會變成什麼樣的東西？
隨機刺激 Random Input（5 題）▶
抽一個完全無關的隨機詞彙，強迫跟主題湊在一起，逼出意外連結；每次抽詞來自三個互斥詞池。
  1. 你們目前的方向或想解決的領域大致是什麼？就算還很模糊也沒關係。
  2. （隨機詞 1）想一下這個詞帶給你的感覺、特性或畫面，硬套進你們的主題，逼出一個點子。
  3. （隨機詞 2）一樣不用管合不合理，抓住它的感覺或特性，跟主題湊在一起，想出另一個點子。
  4. （隨機詞 3）同上，再想出第三個點子。
  5. 剛剛三次的隨機聯想裡，哪一個組合你覺得比較有潛力？再稍微延伸一下這個方向。
Crazy 8s（9 題，每題限時 30 秒）▶
針對同一個具體問題，不准評論、不准刪除，先求數量；越後面擠出來的往往越有突破性。
  1. 你們想解決的具體問題或挑戰是什麼？盡量講清楚，這一步不用想解法。
  2. 解法 1/8：30 秒內寫下第一個解決辦法。不管好不好、可不可行。
  3. 解法 2/8：不要回頭看剛剛寫的，再寫一個解法，這次刻意換一個完全不同的切入角度。
  4. 解法 3/8：繼續，30 秒內寫下第 3 個解法。
  5. 解法 4/8：過半了，第 4 個解法，越怪越好，先不要評論自己。
  6. 解法 5/8：如果卡住，故意想一個誇張、不可行的版本也可以。
  7. 解法 6/8。
  8. 解法 7/8：只剩最後兩個。
  9. 解法 8/8：最後衝刺！通常最後擠出來的最有突破性。
彙整產出：1 個解法 = 1 個 Concept（不合併、不淘汰），數量依實際寫出的解法數而定
多人接龍 Relay（2 人以上，手機同時作答）▶
紙本 Brainwriting 線上版：每人手上一條鏈同時往右傳，看不到別人手上的紙，最後公布牆一次揭曉所有鏈。目前第 1 階段固定三段題目、不呼叫模型。
  1. 主持人按「開始發想」開場，畫面顯示 QR code（自動帶入區網 IP，或 ngrok 網址）
  2. 參與者用手機掃碼加入 lobby
  3. 第 1 層（使用者）：限時寫一兩句，描述一種使用者
  4. 紙往右傳一位 → 第 2 層（場景）：接著剛剛那位寫的使用者，限時寫他會遇到的場景（只往下接、不能改上一層；看不懂也要照樣接）
  5. 3 人以上才有第 3 層（卡點）：接著場景，限時寫他卡在哪裡；2 人時流程縮成「使用者→卡點」兩層
  6. 全部寫完後，主持人畫面一次公布所有完整的鏈
1 人團隊時這個方法完全不會出現在推薦或選項裡（min_team_size）
彙整 → ④ 想法牆 → Idea Synthesizer▶
走完任一方法的全部步驟後固定觸發一次彙整，產出的候選想法進入想法牆；使用者可挑幾個交給 Synthesizer 整合。
  1. 彙整 Agent 讀完整問答歷程＋每一步的想法片段，去重合併成 2~4 個 Project Concept（痛點導向固定 3 個、Crazy 8s 等於解法數），只整理不排序、不淘汰
  2. 候選想法進入想法牆，使用者可以勾選想要的幾個，也可以直接回到 Method Selector 換一種方法再跑一輪（同一輪或新的一輪）
  3. 勾選後交給 Idea Synthesizer Agent：讀所有選中的候選想法（含各自來源方法），找出可組合延伸的地方
  4. 輸出 1~3 個新的整合版 Project Concept，標註 title（直接講功能）＋ description（參考了哪些原始想法元素、為何這樣組合有價值）
