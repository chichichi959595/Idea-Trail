# 隨機刺激（Random Input）

準備一堆跟主題完全無關的詞彙卡（例如：潛水艇、爆米花、仙人掌）。
隨機抽一張，強迫把這個詞的特性跟手上的題目湊在一起，用不合理的連結逼出跳脫慣性的想法。

##### 適合 :
- 已經有方向的 hackathon 之類的
- 卡在「解法都差不多」的時候——**不是**用來找題目的

---

## 原本的問題：題目太模糊，隨機詞就沒東西可以撞

現在第一步問的是「你們目前的方向或想解決的領域大致是什麼？**就算還很模糊也沒關係**」。

這是這個方法最大的破口。模糊的主題 × 隨機詞 = 兩個模糊的東西相乘，
撞出來的只會是「校園 App 可以加一個像仙人掌一樣的功能」這種廢話。

隨機刺激能work的前提，是**被撞的那個東西夠硬**。
題目越具體，隨機詞造成的變形才越明顯、越有意思：

| 題目 | 隨機詞 | 撞出來的東西 |
| --- | --- | --- |
| 「校園服務」（模糊） | 潛水艇 | 「可以潛入校園各角落的服務」← 廢話 |
| 「宿舍幹部每學期要人工核對 300 份繳費單，最怕漏掉一筆」（具體） | 潛水艇 | 潛水艇是**分艙**的，一艙進水不會沉船 → 繳費單分批封存，每批獨立對帳，錯了只重查那一批 |

## 改法：題目改用「團體發想出來的痛點」

不要再問使用者「你們的方向是什麼」，直接從**情境庫**撈一個真人寫過的具體痛點當題目。
（情境庫是多人接龍累積下來的材料，見 `多人接龍.md`。）

```
一個具體痛點（真人寫的，固定不變）
   × 隨機詞 1  →  解法 1
   × 隨機詞 2  →  解法 2
   × 隨機詞 3  →  解法 3
   → 挑一個延伸
```

痛點**全程固定**，變的只有隨機詞。這是刻意的：三次撞擊打的是同一個靶，
所以三個解法可以直接放在一起比，不是三個互不相干的方向。

痛點的來源有三種，由使用者在開始前選：

1. **本次接龍的某一條鏈** — 剛剛大家一起寫出來的，現場記憶最新
2. **情境庫裡的舊鏈** — 上個月工作坊沒被選中的那些，不用重新發想
3. **自己打** — 沒跑過接龍也要能用，這條路不能斷

## 現在的流程要改的地方

`backend/app/agents/framework/random_input.py` 已經有三組互斥的詞池（A/B/C）
和三個隨機詞步驟，機制是完整的。要改的是**題目那一步**和**用字**：

### 1. 第一步變成可以被外部填答

```python
class RandomInputAgent(FrameworkAgent):
    seed_step = "topic"
    """接受外部起點：一條接龍的鏈、或情境庫裡的舊痛點。
    填進來之後從第二步開始跑（見 `多人接龍.md` 的「起點（seed）」）。"""
```

沒有 seed 的時候照樣能自己打，但題目的問法要改掉「就算還很模糊也沒關係」：

```python
StepSpec(
    "topic",
    "你們想解決的具體痛點是什麼？要具體到講得出「誰、在什麼時候、卡在哪裡」，"
    "越具體後面的隨機聯想才越有東西可以撞。",
)
```

### 2. 要的是「解法」，不是「點子」

現在三個隨機詞步驟都寫「逼出一個**點子**」。既然題目已經是一個具體痛點，
要的就該是**針對這個痛點的解法**：

```python
f"不用管合不合理，想一下「{word}」的特性、結構或畫面——"
f"它怎麼運作？它最像什麼？然後硬套到上面那個痛點上，逼出一個解決辦法。"
```

多加一句「它怎麼運作？它最像什麼？」是有理由的：
大部分人拿到隨機詞會停在**表面聯想**（仙人掌 → 綠色、有刺），
要的其實是**機制聯想**（仙人掌 → 平常不需要照顧，但能撐很久 → 一個平常不用管、
但關鍵時刻一定在的東西）。後者才會撞出東西。

### 3. 痛點要一直掛在畫面上

三個隨機詞步驟的畫面上，那個痛點要**一直看得到**，不能只在第一步出現。
不然寫到第三個隨機詞時，人已經飄到隨機詞本身去了，忘記自己在解什麼。

### 4. 彙整：一個隨機詞一個候選，全部保留

```python
def finalize_spec(self, all_steps) -> FinalizeSpec:
    # 三個隨機詞 → 三個解法 → 三個候選，不合併不淘汰。
    # 理由跟 Crazy 8s 一樣：這是發散階段，篩選是想法牆之後的事。
    # pick_best 那一步的延伸內容，併進它對應的那個候選裡。
    return FinalizeSpec(material=..., min_items=3, max_items=3)
```

## 為什麼這樣才是 web LLM 做不到的

「隨機抽一個詞跟主題結合」——這件事 ChatGPT 一句 prompt 就做得到，而且做得不錯。

差別在**那個痛點是從哪裡來的**：

- ChatGPT：你要自己想一個題目講給它聽，通常就是你腦袋裡現成的那個，所以撞不出你想不到的東西
- 這裡：題目是**一群人接龍寫出來的**，而且可以是**幾個月前別人寫的**、你從來沒看過的

隨機詞是公開的（詞池誰都有），**真人寫過的具體痛點才是私有資料**。
所以這個方法的價值不在隨機，在那個靶。
